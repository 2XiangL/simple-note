# 设计：英文语言支持（系统语言自动切换）

日期：2026-08-16
状态：已批准

为 Simple Note 增加英文界面支持：启动时检测系统语言，系统语言为中文（任何中文变体，含繁体）则显示简体中文界面，否则全部 UI 文案显示英文。

现状痛点：全部 UI 文案硬编码为简体中文，散布在 app/toolbar/notes_panel/tray/search_dialog/reminder_dialog/notify/reminder/main 约 9 个模块；英文用户只能看到中文界面。

## 方案选型

- **方案 A（采用）**：自建 `lang.py` 纯 Python 模块（Tk-free，风格对齐 `util.py`），`t(key)` 函数 + 英文翻译字典，**中文串即 key**。零新增依赖、零打包改动（`SimpleNote.spec` 不动）、测试可强制指定语言、与项目"小型纯逻辑模块"的既有风格一致。
- 方案 B（否决）：GNU gettext（.po/.mo 工具链）。需维护 .po 文件并把 .mo 作为数据文件打进 exe（spec 改动），对"启动时锁定、仅两套语言"的场景过重。
- 方案 C（否决）：gettext API + 内嵌 Python 字典。同时引入 gettext API 形态与工具链心智，收益为零。

## 非目标（YAGNI）

- 不做运行期语言切换（菜单里手动切换语言）——语言在启动时锁定
- 不做繁体中文第三套界面翻译——任何中文系统一律显示简体中文界面
- 不做 `gettext` 工具链/`.mo` 文件

## 新模块 `lang.py`

Tk-free 纯逻辑模块，供所有 UI 模块（含 Tk-free 的 `reminder.py`/`notify.py`）调用。

### API

| API | 职责 |
|---|---|
| `detect_system_language()` | 返回 `"zh"` 或 `"en"`。Windows：`ctypes.windll.kernel32.GetUserDefaultUILanguage()` 取 LCID，**主语言 ID（低 10 位）== 0x04（LANG_CHINESE）→ "zh"**（zh-CN/zh-TW/zh-HK/zh-SG/zh-MO 全覆盖，含 `0x0804`/`0x0404`/`0x0c04`/`0x1004`/`0x1404`）；非 Windows 或调用失败 → 回退 `locale.getlocale(locale.LC_CTYPE)`（再退 `os.environ.get("LANG")`）前缀 `"zh"` 判断；仍无法判定 → `"en"`（英文兜底，符合"否则一律英文"） |
| `set_language(code)` | 显式覆盖语言（main.py 启动时调用；测试用）。传入非 `"zh"`/`"en"` 视为 `"en"` |
| `get_language()` | 返回当前语言；模块级 `_lang` 为 `None` 时惰性调用 `detect_system_language()` 并缓存 |
| `t(key)` | 取当前语言的文案。zh 模式原样返回 key；en 模式查 `EN_TRANSLATIONS`，缺 key 回退 key 本身（漏译只退化为中文，绝不返回空/抛异常）。支持 `%` 格式化：`t("共 %d 处") % n` |

### 数据

- `EN_TRANSLATIONS`：`dict`，键为中文原文，值为英文译文。格式化占位符（`%d`/`%s`/`\n`）原样保留在键与值中，调用方 `t(...) % args` 展开。
- zh 不需要字典（key 即文案），杜绝中文重复维护。

## 启动时机

`main.py` 第一实例启动路径最开头（早于 Pillow 探测与任何 Tk 创建）：

```python
import lang
lang.set_language(lang.detect_system_language())
```

`get_language()` 的惰性检测兜底保证任何遗漏路径下 `t()` 也可用。语言全局锁定，运行期不变。

## 各模块接线（全部 UI 文案过 `t()`）

| 模块 | 改动 |
|---|---|
| `app.py` | 全部菜单/级联标题（文件/编辑/查看/提醒/关于 等）、`NOTE_FILTER`（"所有文件"）、`NoteDocument` 默认标题"新建笔记"、filedialog 标题（打开笔记/打开工作区/另存为）、全部 messagebox 标题与文案（打开失败/保存失败/工作区汇总/未保存确认/关于 Simple Note）。**行距单选 `label=t(name)` 但 `value=name` 保持中文内部键**，`_on_line_spacing` 与持久化链路不变 |
| `toolbar.py` | 颜色按钮、`colorchooser.askcolor` 标题 |
| `notes_panel.py` | 右键菜单：保存/另存为/关闭 |
| `tray.py` | pystray 菜单项：显示/隐藏、退出（后台线程建菜单时只读翻译 dict，启动后无写入，线程安全） |
| `search_dialog.py` | 窗口标题、上一个/下一个按钮、区分大小写、"共 %d 处"/"无匹配" 状态文案 |
| `reminder_dialog.py` | 窗口标题、全部 LabelFrame/Label/Button/Radiobutton/Treeview 表头、列表单元格值（一次性/每日/"每天 %02d:%02d"）、全部警告弹框标题与文案（参数格式不正确/请填写内容/时间格式不正确/时间超出范围/日期格式应为/时间必须晚于当前）、试听提示 |
| `notify.py` | `format_events`：标题"提醒"、拼接格式 `"%s：%s"` → `t("%s：%s")` |
| `reminder.py` | 番茄钟阶段（工作中/休息中/"第%d/共%d轮"）、事件标题与消息（番茄钟完成/工作结束/休息结束/提醒/每日提醒）→ 事件构造时 `t()`。**用户录入的提醒 label 是内容数据，绝不翻译** |
| `main.py` | Pillow 缺失警告弹框文案 |
| `image_resizer.py` | 不改（纯视觉浮层，无文案） |
| `util.py`/`snote.py`/`imefont.py`/`settings.py`/`singleinstance.py` | 不改。`settings.py` 零改动：`紧凑/标准/宽松` 作为持久化内部键原样保留（向后兼容现有 settings.json），仅显示层翻译。stderr 开发者警告（tray/singleinstance/reminder）属开发者输出而非 UI，保持中文 |

## 测试

- `tests/conftest.py` 增加 autouse fixture：每个测试前后 `set_language("zh")`（restore 原值）——现有断言中文文案的测试（test_reminder/test_notify/test_search_dialog/test_app/test_reminder_dialog/test_settings 等）在任何系统语言下确定通过，**一行不改**。
- 新增 `tests/test_lang.py`（无显示器可跑）：
  - `detect`：monkeypatch Win32 `GetUserDefaultUILanguage` LCID（`0x0804`/`0x0404`→zh，`0x0409`→en）；非 Windows 路径 monkeypatch `locale`/`LANG`（`zh_CN.UTF-8`→zh，`en_US`→en，空→en）
  - `t()`：zh 原样返回 key；en 返回译文；en 缺 key 回退 key；`%` 格式化展开正确
  - `set_language`/`get_language`：覆盖生效、非法值归 `"en"`、惰性检测缓存

## 文档同步

- `AGENTS.md`：Architecture 增加 `lang.py` 条目；Conventions 的"UI 字符串写简体中文"改为"UI 文案一律经 `lang.t()`，中文串即 key，英文译文进 `EN_TRANSLATIONS`；docstring 仍写中文"

## 兼容性

- 不新增依赖（纯标准库）；`SimpleNote.spec` 无需改动
- 中文系统行为与现状完全一致（zh 模式 `t(key)` 原样返回 key）
- `settings.json` 持久化格式不变，旧配置文件兼容
